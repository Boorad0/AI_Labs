# ЛР1
**Цель работы**

Освоить базовый программный цикл взаимодействия с LLM и научиться сравнивать несколько моделей на одинаковом наборе заданий.

**Описание моделей**

Qwen3.5 — это семейство больших языковых моделей от компании Alibaba Cloud, выпущенное в феврале 2026 года. Оно включает несколько вариантов с разным количеством параметров (от 0.8B до 397B), что позволяет подобрать решение под конкретные задачи: от запуска на ноутбуке до работы с огромными массивами данных в облаке.

Gemma 4 — это четвёртое поколение семейства открытых мультимодальных больших языковых моделей (LLM) от Google DeepMind. Её выпустили 2 апреля 2026 года. Модель построена на тех же исследованиях и технологиях, что и закрытая флагманская модель Gemini, но в отличие от неё Gemma 4 распространяется с открытыми весами под разрешительной лицензией Apache 2.0, что позволяет свободно использовать её в коммерческих целях, модифицировать и распространять.

**Способ доступа**

LM Studio развернута на домашнем ПК. Запросы к модели отправляются с ноутбука. Для установления соединения между ноутбуком и домашним ПК на обоих устройствах запущен Radmin VPN, обеспечивающий их взаимодействие через виртуальную частную сеть.

**Запуск**
Установить зависимости:
```
pip install -r requirements.txt
```
Создать .env на основе примера и указать реальные значения:
```
cp .env.example .env
```
Запустить LM Studio, загрузить нужную модель и включить локальный сервер (обычно на порту 1234). Проверить, что нужная модель реально загружена:
```
curl http://localhost:1234/v1/models
```
Запуск кода:
```
python main.py
```
**Переменные окружения**
```
API_TOKEN=      # Токен LM_Studio
LMM_BASE_URL=   # адрес сервера, по умолчанию http://localhost:1234/v1
LMM_MODEL_1=    # точное имя модели 1, загруженной в LM Studio
LMM_MODEL_2=    # точное имя модели 2, загруженной в LM Studio
```
**Результаты**
в results.json

Gemma-4-12b-it-qat в отдельных случаях допускала ошибки, связанные с точностью и соблюдением ограничений задания. Таким образом, в рамках проведённого эксперимента Qwen3.5-9b показала лучшие результаты как по качеству ответов, так и по скорости выполнения запросов. Полученные результаты подтверждают, что выбор LLM должен основываться на результатах тестирования, а не только на субъективной оценке ответов.

**Ответы на контрольные вопросы**

**1. Что такое API и зачем он нужен при создании AI-приложений?**

**API (Application Programming Interface)** — это программный интерфейс, который позволяет вашему коду взаимодействовать с языковой моделью (LLM). В контексте AI-приложений API нужен для того, чтобы встраивать возможности нейросети (анализ текста, генерацию, маршрутизацию данных) напрямую во внутренние продукты, CI/CD-пайплайны или скрипты. Это избавляет бизнес от необходимости самостоятельно разворачивать и поддерживать ресурсоемкие модели на своих серверах.

**2. Чем работа с LLM через API отличается от использования чат-интерфейса?**

Веб-интерфейс (как ChatGPT или GigaChat) предназначен для ручной работы: система сама хранит историю переписки и имеет удобный GUI.

При работе через API приложение берет управление на себя:

- **Контекст:** API является «stateless» (не сохраняет состояние). Разработчик должен вручную передавать нужную часть истории сообщений в каждом новом запросе.
- **Управление поведением:** через API можно тонко настраивать параметры генерации (например, temperature, top\_p) и запрашивать строгий формат ответа (JSON).
- **Автоматизация:** API-агенты могут самостоятельно вызывать функции (Tool Calling) и обращаться к корпоративным базам данных без участия человека.

**3. Какую роль выполняет system message?**

**System message (системный промпт)** определяет глобальную модель поведения нейросети. Он задает роль (например, «Ты — senior-разработчик баз данных»), ограничения, формат вывода и погружает модель в контекст предметной области. Однако системный промпт — это инструкция в вероятностной системе, а не жесткий программный барьер безопасности. Он не гарантирует 100% защиту от инъекций (prompt injection).

**4. Почему нельзя сравнивать модели только по одному запросу?**

LLM — это вероятностные алгоритмы, и их производительность сильно варьируется в зависимости от домена. Модель, выдавшая блестящий текст на один креативный запрос, может полностью провалить задачу по извлечению фактов или написанию кода. Объективно оценить модель можно только на больших бенчмарках (тысячи примеров), которые тестируют ее поведение в пограничных случаях (edge cases) и стабильность следования инструкциям.

**5. Почему один и тот же запрос может давать разные ответы?**

При генерации ответа LLM не просто «вспоминает» текст, а предсказывает вероятность появления следующего токена. Ключевой параметр temperature регулирует степень случайности этого выбора. При temperature > 0 модель выбирает не только самые вероятные токены, что делает текст разнообразным. Даже при нулевой температуре могут возникать минимальные различия из-за особенностей вычислений с плавающей точкой на графических процессорах (GPU).

**6. Что такое latency и почему она важна для бизнес-приложения?**

**Latency (задержка)** — это время, которое требуется модели для обработки запроса. Она измеряется параметрами TTFT (Time To First Token — время до первого слова) и общей скоростью генерации. Для бизнеса высокая задержка критична: она ухудшает пользовательский опыт (UX) в чат-ботах, вызывает таймауты (504 Gateway Timeout) при интеграции нескольких микросервисов и делает невозможным использование ИИ в задачах реального времени.

**7. Почему API-ключ нельзя хранить в публичном исходном коде?**

Если API-ключ попадет в публичный репозиторий (например, на GitHub), он будет моментально обнаружен автоматическими ботами-скрейперами. Это приведет к несанкционированному использованию ваших квот, исчерпанию лимитов платформы (ошибка 429), блокировке ключа (ошибка 401) и крупным финансовым потерям, за которые придется платить владельцу ключа.

**8. Какие данные нельзя отправлять во внешнюю LLM без соответствующих оснований и мер защиты?**

Во внешние публичные API категорически не рекомендуется отправлять:

- Персональные данные (ПДн) сотрудников или клиентов.
- Коммерческую тайну и интеллектуальную собственность (включая проприетарный код).
- Ключи, пароли и токены доступа, которые могут оказаться в логах или дампах баз данных.

Для безопасной работы используются корпоративные подписки (с гарантией неиспользования данных для обучения) и внутренние прокси-шлюзы, которые динамически анонимизируют чувствительные данные перед отправкой в LLM.

**9. Какие метрики классического машинного обучения подходят только для части LLM-задач?**

Классические метрики, такие как **Accuracy (точность), Precision, Recall и F1-score**, отлично подходят для LLM-задач классификации (например, определение тональности отзыва). Но они абсолютно бесполезны для оценки сгенерированного текста (саммаризация, перевод). Для генеративных задач применяются метрики перекрытия n-грамм — **ROUGE** (оценка полноты) и **BLEU** (оценка точности), а также оценка ответов с помощью других мощных нейросетей (LLM-as-a-Judge).

**10. Почему высокая скорость модели не означает высокое качество?**

Скорость работы нейросети обычно повышается за счет уменьшения количества параметров (например, использование моделей на 7B-8B параметров) или снижения точности весов (квантование). Такие быстрые модели хорошо подходят для простых рутинных задач, но им физически не хватает «вместимости» для глубокого логического вывода (reasoning) или удержания сложного контекста по сравнению с флагманскими тяжелыми моделями.

**11. Какие ошибки могут возникать при вызове API и как приложение должно на них реагировать?**

Базовые сценарии обработки ошибок:

- **429 Too Many Requests:** Превышение квот на токены (TPM) или запросы (RPM). **Реакция:** Обязательное использование алгоритма экспоненциальной задержки (Exponential Backoff) с проверкой заголовка Retry-After.
- **401 / 403 Unauthorized:** Проблемы с API-ключом или балансом. **Реакция:** Остановка попыток вызова API, создание алерта для мониторинга.
- **500 / 502 / 504:** Внутренние ошибки серверов провайдера. **Реакция:** Повторная попытка (Retry) или маршрутизация запроса на резервную LLM (Fallback).

**12. Какие дополнительные критерии вы бы добавили при выборе модели для корпоративной системы?**

При проектировании корпоративной архитектуры помимо скорости и качества учитывают:

1. **Формат развертывания (On-Premise vs Cloud):** Возможность развернуть модель в закрытом контуре компании (на собственных серверах) для строгого соответствия регламентам ИБ.
2. **Экономика токенов:** Стоимость ввода (input) и вывода (output) за 1 миллион токенов, так как при масштабировании это становится главной статьей расходов.
3. **Размер контекстного окна:** Способность модели обрабатывать от 128k токенов и выше для работы с объемной документацией (RAG-пайплайны).
4. **Совместимость API:** Поддержка форматов (например, OpenAI-совместимый API), что позволяет бесшовно менять модели без переписывания бэкенда.
5. **Service Level Agreement (SLA):** Юридические гарантии аптайма и доступности от провайдера LLM.
